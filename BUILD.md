# OMBRA — production build

Vite + React + TypeScript recreation of the `OMBRA.dc.html` design reference.
Plain inline styles + one global stylesheet, no UI kit.

## Run

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # tsc -b && vite build → dist/
npm run preview    # serve the production build
```

## The film & frame-sequence pipeline

Scroll-scrubbing a compressed video by seeking `currentTime` is choppy (every
seek restarts decode from the nearest keyframe). Instead the default **frame-scrub**
mode draws a **pre-decoded frame sequence** to a `<canvas>` — perfectly smooth,
exactly scroll-locked.

All derived media lives in `public/` and is regenerated by one script:

```bash
npm run assets           # = bash scripts/build-assets.sh [sourceFilm]
```

It produces, from `uploads/77316-561991002.mp4` (1920×1080, 60fps, 60.7s):

| Output | How | Used by |
|---|---|---|
| `public/film.mp4` | `ffmpeg -c copy -movflags +faststart` | drift mode (`moov` moved to front) |
| `public/film.webm` | VP9 (`libvpx-vp9 -crf 34`) | drift mode (lighter decode) |
| `public/film-poster.jpg` | single frame @1.5s | `<video poster>` + reduced-motion freeze |
| `public/frames/001…1458.jpg` | `fps=24, scale=960:-1` (~1458 frames) | frame-scrub canvas |
| `src/frames-meta.json` | 48×27 gray raw → node centroid pass | reactive figure layer |

**Frame density = scrub smoothness.** The page scrolls ~6200px; at 1458 frames
that's ~4.3px of scroll per frame, so the film steps imperceptibly and reads as
smooth 60fps. Sparser sequences (e.g. 150 frames → ~41px/frame) visibly stutter.
Frames are ~8.5KB each (~12MB total), and they're decoded on demand (bounded RAM),
so density is cheap — raise/lower `FPS` in `scripts/build-assets.sh` to trade
smoothness against weight. The luminance pass uses the **same `fps`** so centroid
index N lines up with frame N exactly.

## How it runs (single rAF loop → CSS vars)

`src/hooks/useFilmStage.ts` owns one `requestAnimationFrame` loop. It writes only
CSS custom properties on `<html>` (`--mx --my --mp --p`) plus a few `textContent`
updates — no per-node listeners, no layout thrash.

- **Frame-scrub (default).** Scroll progress → target frame; the float index eases
  toward it (`0.2` lerp); the nearest frame is cover-fit drawn to the canvas, and
  only when the rounded index changes. The figure centroid is read from the
  build-time lookup in `frames-meta.json`.
- **Apparition trail (the scroll signature).** While scrolling, the canvas is
  dimmed each frame by a velocity-dependent black veil and the current frame is
  stamped with `lighten`, so the bright figure smears into fading ghosts of
  itself — the faster you scroll, the longer the trail. At rest the ghosts
  dissolve in under a second and a single clean silhouette remains; the stage
  scale "breathes" (1.04→1.06) with the same velocity. Tuning lives in
  `useFilmStage.ts` (`velNorm` divisor 48, veil `0.26 − 0.2·heat`).
- **Smooth drift.** The `<video>` plays natively; scroll velocity ramps
  `playbackRate` (`+` up to ~3.4×, `0.06` lerp) and eases back to idle
  (`baseSpeed`, default 0.5×). No seeking. Centroid is sampled live from a 48×27
  offscreen canvas — the original prototype behaviour.
- **Reactive layer.** `--mx/--my/--mp` (eased) drive the eyeline + live `FIGURE X/Y`
  readout, the spotlight, and the hero/apparition heading "dodge". Absent figure →
  centre, instruments fade.
- **Reveals.** `IntersectionObserver` (`src/hooks/useReveals.ts`): mask-rise for big
  headings, fade+rise+blur for the rest, first-viewport immediate, 6s safety net.
- **Reduced motion.** `prefers-reduced-motion` freezes the film on a still frame,
  skips reveal animation, and disables playback.

### Modes & options (URL query, spec defaults otherwise)

```
?motion=drift      smooth-drift instead of frame-scrub (default: scrub)
?accent=#C9A227    accent from {A9B4C0, C9A227, B4472E, 8E97A6, E3DCCB}
?grain=0           disable film grain
?fig=0             hide the FIGURE X/Y instruments
?speed=0.7         drift idle speed (0.2–1.5)
```

## Imagery — 11 slots

Drop real photography into `public/images/` named by slot id and it wires
automatically (else a refined empty well shows):

```
rom-piece-1.jpg … rom-piece-6.jpg     collection (3:4)
rom-look-1.jpg (3:4)  rom-look-2.jpg (4:5)  rom-look-3.jpg (1:1)  rom-look-4.jpg (3:4)
rom-house-portrait.jpg                 house portrait (3:4)
```

Keep every image high-contrast **black-and-white on black**. See `IMAGE_PROMPTS.md`.

The 11 shipped images are AI-generated (Nano Banana Pro, regenerable) — see
`IMAGE_MANIFEST.md` for the model, seeds, and per-slot prompts. Drop real studio
photography over them anytime using the same filenames.

## Figure-driven negative aesthetic

As the tracked film figure moves, the areas it passes under invert:
- The big section headings use `mix-blend-mode: difference`, so they flip to dark
  where the bright figure passes behind them (`src/components/sections/*`).
- A **figure-tracking negative lens** (`src/components/NegativeLens.tsx`, z-index 4)
  is a soft `difference` ellipse centred on `--mx/--my`, gated by presence `--mp` —
  a travelling "negative pocket" (black ground → white, pale figure → dark). It sits
  above content but below the chrome, so nav/status stay readable. Disabled under
  `prefers-reduced-motion` (headings' static blend stays).
